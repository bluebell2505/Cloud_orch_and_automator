How it works

From failure to fix
in under 60 seconds.

The entire pipeline fires automatically the moment GitHub Actions fails. No manual commands needed.

01 · DETECT
Webhook trigger
GitHub fires a webhook the instant a workflow fails. PipOtter receives it and immediately starts processing the event.
POST /webhook
02 · FETCH
Log extraction
Real CI logs are pulled from GitHub API, cleaned of timestamps and noise, compressed to the most relevant 60 lines.
GitHub Actions API
03 · DIAGNOSE
AI diagnosis
Mistral LLM classifies failure type, finds root cause, and returns a structured JSON fix plan with a confidence score.
Mistral via Ollama
04 · FIX
Auto remediation
Opens a PR, retries the pipeline, or emails the owner — decided by failure type and how confident the AI is about it.
PyGithub + SMTP
05 · RECORD
Persist outcome
Every event — diagnosis, action taken, and result — is written to PostgreSQL for metrics, dashboards, and future learning.
PostgreSQL
06 · VISUALIZE
Live dashboard
MTTR, fix success rate, failure types, and confidence scores — all live and updating in real time on Grafana.
Grafana

Remediation engine

Four ways PipOtter
fixes your pipeline.

Open a fix PR
For dependency errors, PipOtter creates a branch, patches the broken file with the correct version, and opens a Pull Request automatically.
dependency_error → patch_dependency
Retry the pipeline
For flaky tests or transient failures, PipOtter re-triggers the workflow run via the GitHub Actions API without any human touch.
flaky_test → retry
Email the owner
When confidence drops below 65% or failure is too complex, a rich HTML diagnosis email is sent to the repo owner for manual review.
confidence < 0.65 → notify_human
Fix config + retry
For missing environment variables or config mismatches, PipOtter injects the correct values and retriggers the pipeline in one shot.
config_error → fix_config
